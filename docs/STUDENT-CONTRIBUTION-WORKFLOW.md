# Student Contribution Workflow

## NEXORA Student Chapter – VIIT

This document outlines the student development model and peer mentorship structure at **NEXORA Student Chapter – VIIT**. Our contribution model is designed to guide students from their initial interest to publishing clean, production-ready code.

---

## 1. Student Development Model

Every contribution in NEXORA follows a supportive, step-by-step lifecycle:

```text
       Contributors / Students
               │
               ▼
        Project / Issue
               │
               ▼
            Branch
               │
               ▼
          Development
               │
               ▼
         Pull Request
               │
               ▼
    Technical Team Review
               │
               ▼
           Feedback
               │
               ▼
         Improvements
               │
               ▼
            Approval
               │
               ▼
             Merge
               │
               ▼
    Contributor Recognition
```

---

## 2. Technical Team Structure

Our organization is structured with `technical-team` as the active core technical group, while `contributors / Students` represents the future contributor structure:

```text
NEXORA-VIIT-ORG
│
├── technical-team
│   ├── Technical Lead
│   ├── Technical Members
│   └── Project Leads / Mentors
│
└── contributors
    └── Students
```

> **Note on GitHub Teams**: The `technical-team` GitHub Team is the active technical group within `NEXORA-VIIT-ORG`. Technical Members may act as Project Leads / Mentors for individual projects and guide Contributors / Students during development. The `contributors` group represents the future organizational structure for student contributors.

---

## 3. Role Responsibilities & Governance

### Technical Lead
- **Architecture & Quality**: Ensures project repositories adhere to overall technical standards and security policies.
- **Organization Management**: Manages repository creation, project approvals, and release workflows.
- **Mentorship Standards**: Guides technical members in conducting constructive, educational code reviews.

### Technical Members
- **Project Guidance & Mentorship**: Act as Project Leads / Mentors for assigned projects, guide Contributors / Students, and assist with Git/GitHub workflows.
- **Code Reviews**: Review student Pull Requests promptly, offering clear, encouraging, and educational feedback.
- **Workflow Guidance**: Assist first-year students and Contributors / Students in understanding Git branching, rebase/merge concepts, and local testing.
- **Issue Triage**: Help categorize incoming bug reports, feature requests, and tag beginner-friendly issues (`good first issue`).

### Project Leads / Mentors
- **Project Guidance**: Maintain project roadmaps, define issue scope, and coordinate feature deliverables.
- **Hands-On Mentorship**: Act as dedicated mentors for assigned projects, holding check-ins and answering contributor questions.
- **Review & Approval**: Review project-specific PRs and approve changes ready for integration into main branches.

### Contributors / Students
- **Learning & Growth**: VIIT students who participate in open-source development, learn software engineering concepts, and build projects.
- **Active Development**: Pick up issues, write clean code, test locally, submit Pull Requests, and respond to review comments.
- **Portfolio Building**: Build a public, verifiable record of contributions on GitHub to showcase technical skills.

---

## 4. Educational Peer Review Process

Code review at NEXORA is a **learning conversation**, not an evaluation gate:

1. **Submit Early**: Students are encouraged to open draft PRs early if they need help or feedback mid-development.
2. **Supportive Feedback**: Mentors highlight what was done well and explain *why* a particular change or improvement is suggested.
3. **Iterative Refinement**: Students implement suggestions, ask follow-up questions, and update their PR.
4. **Recognition**: Once merged, contributors are celebrated across NEXORA channels and acknowledged in project documentation!
